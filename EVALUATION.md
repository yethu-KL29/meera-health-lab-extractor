# Frozen scoring protocol

Defined before changing extraction. Original `gold/` is preserved. Label audits, if any, must be source-backed and reported separately; use `--labels` to report both original and audited scores, never silently replace labels.

Match names using case/punctuation normalization and explicit aliases in `evaluate.py`; no fuzzy or result-dependent matching. Repeated names match by occurrence. Unknown aliases remain errors. No cross-unit numerical conversions. Numeric strings and numbers compare equally, including comma grouping and trailing zeros. Whitespace around range punctuation and micro-symbol spelling are normalized. Comparator direction, qualitative wording, missing data, units, and range endpoints remain significant. Null differs from empty strings and zero. Full row correctness requires a matched name and correct value, unit, and reference range. Extra output fields are not scored.

Primary metric: micro strict-row F1. Precision = fully correct rows / predicted rows; recall = fully correct rows / expected rows. Missing and extra rows hurt the score. Field accuracy uses all expected rows as denominator, so omissions count as incorrect. Also retain per-report field errors, extra rows, schema failures, individual latency, and token usage. This is intentionally conservative: undiscovered name synonyms can reduce scores; review error records rather than tuning aliases after seeing improvements. Row order is inspected separately; it is not captured by the aggregate F1.

Run every report, including four unlabelled documents. Do not include unlabelled reports in quantitative accuracy without independent source-backed annotations. Review their outputs against the documents and record the review method and limits. Agent inspection is not human verification. Eight labelled reports are a small development set, not an unbiased estimate of unseen-report performance.

End-to-end elapsed time includes local preprocessing and all model calls for one report. One sequential run is not a latency benchmark. Usage is recorded directly from API responses. List-price estimates require a cited rate and correct treatment of billed thinking tokens; actual account spend is not inferred from token counts. Failed calls may still have cost not observable in a response. Do not present missing usage as zero cost.

Baseline is `baseline.py`, copied unchanged from the starter `extract.py`. Run directories store source/scorer hashes, exact model, UTC timestamp, predictions, usage, latency, and errors; existing directories cannot be overwritten by a new run. `--score-only` rescores saved outputs without model calls.
