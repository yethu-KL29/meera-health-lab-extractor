# Run provenance

All calls used the supplied reports; these are development results, not hidden-test scores. Credentials and request headers are excluded.

| Directory | Role |
|---|---|
| `baseline/` | Incomplete original-model attempt, interrupted before first extraction returned; metadata only, not scored. |
| `baseline-flash-lite/` | Canonical unchanged baseline, access substitution to gemini-3.1-flash-lite, 60 DPI, one PDF page. |
| `final/` | Development failure: PDFium pages do not support `with page`; eight PDFs failed locally. Retained rather than hidden. Fixed with explicit page cleanup and an all-pages regression check. |
| `final-150dpi/` | Initial corrected PDF renderer, before HTTP retry support. Reports 04 and 11 failed without usage; diagnostic reruns succeeded. The original harness retained only error class for these failures, so their HTTP status is unknown. |
| `final-verified/` | Canonical final, 150 DPI, all pages, schema-constrained transcription, one bounded retry on HTTP 429/5xx. This complete run contains captured HTTP 503s followed by successful responses. |
| `experiment-300dpi/` | Controlled higher-resolution experiment using the identical final extractor/model/prompt, with EXTRACT_DPI=300. |
| `baseline-35-flash-lite/` | User-requested gemini-3.5-flash-lite comparison; unchanged baseline, 60 DPI, first page. |
| `final-35-flash-lite/` | Same improved pipeline and scoring, gemini-3.5-flash-lite, 150 DPI, all pages. |

Each report JSON stores its prediction, measured end-to-end latency, response usage, and any terminal error. The later harness also records candidate responses, finish reasons, and HTTP errors; earlier runs do not have these details. `run.json` stores model, timestamp and source/scorer hashes; later runs additionally record rendering and prompt settings. No original measurement is replaced by a diagnostic rerun.

`evaluation.json` scores original labels. `evaluation-gold_audited.json`, where present, applies the separately documented source correction. `comparison.json` is regenerated by `python report_results.py` and includes both scores, per-row errors, per-report token usage, latency, and standard list-price estimates. See `ACCESS.md` for rates, assumptions, and incomplete billing visibility.

Scoring functions and aliases were frozen in commit 30e363c. Later `evaluate.py` changes only extended run metadata, diagnostics and audit output filenames; matching/scoring semantics stayed unchanged. There are 30 baseline predictions that do not match the frozen name aliases; many are harmless expanded names. Thus the primary score gain includes improved source-name fidelity and should not all be interpreted as correction of clinically wrong values. Source-row evidence for page omissions, coerced values and invented ranges is reported separately in README.

Measured final extraction behavior is from commit cf483cf. A later documentation-only edit corrected the extractor docstring to Python 3.11+ because pinned Pillow 13 requires it; the extraction logic is unchanged. The user-requested 3.5 Flash-Lite runs use this same logic with only GEMINI_MODEL changed. Both models use identical prompts, 150 DPI, and scoring.
